# 受入検証の範囲

## テンプレートツール
新規生成、変数検査、既存ファイル保護、lockと基準hash、追加・更新・削除、ローカル独自変更、両側変更、seed保持、計画後の変更、承認digest不一致、path traversal、symlink、payload改変をテストする。

## ハーネスMVP
固定SHA、複数repoの対応、共通範囲の独立調査、他系列出力の遮断、失敗Attemptの再試行、Dの合流条件、矛盾検出、Evidence欠落、Run履歴、承認の失効を検証する。

## 計画とグラフ
runtimeグラフの循環が保持され、Task DAGの循環が検出されることを確認する。
共有DB writerからconsumerへの影響、ライブラリの組み込み版、混在構成、複数PRのChangeSetを検証する。

## 比較とProvider
論理初期状態の一致、独立volume、外部副作用の隔離、非同期収束、正規化の境界、意図差の期限、判定不能、cleanup、EC2接続先違い、権限不足をテストする。

## 合格の意味
スキーマ合格、fixtureテスト合格、実アプリ検証合格、本番切替承認を別々の状態として報告する。
同梱例で確認した事柄は実対象にも適用して観測し、差異をFindingとして残す。
