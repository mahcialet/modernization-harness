# EP-002：照合と統合Inventory

状態：計画。実装進捗は着手時に更新する。

## 目的
照合と統合Inventoryを、根拠とテストで確認できる成果へ分割する。

## 開始条件
EP-001の封印済み出力が揃っている。

## 実施することと理由
1. 同一主張のscopeと根拠を対応付け、confirmed/conflicting/unverified/missingへ整理する。
2. repo横断の呼出元・呼出先・共有DB・JARの関係を照合する。
3. Coverage・Unknown・追加調査方法を含むInventory案を生成する。
4. 人間の承認と有効digestを付けて現在Inventoryへ反映する。

主張と根拠を対応付けてrepo横断の関係を照合し、その結果からInventory案を作る。現在Inventoryへの反映は、人間の承認後に行う。

データや操作の仕様と検証を先に定め、Agentや実環境への接続は後段で具体化する。

## 完了条件
- [ ] 矛盾fixtureの期待差分を検出し、単純な多数決でconfirmedへ変えない。
- [ ] 環境差・バージョン差・本当の矛盾を区別したscopeを記録する。
- [ ] 各重要FindingからEvidenceと固定ソースへ遡れる。
- [ ] 未解決がある場合に、その影響範囲と承認範囲を表示できる。

## PRと証跡
データや操作の仕様、実装、fixture、統合確認をレビュー可能な単位へ分ける。各PRに変更理由、入力Snapshot、実行コマンド、結果、未確認事項を残す。

## 中断・復旧
最後に検証できたcommitとRun/Attemptを記録し、再開時に入力digestと権限を再確認する。外部状態の復元は対象Providerの承認手順で行う。

## 進捗・判断・引継ぎ
着手後に実施済み事項、発見、Decision、残課題、次の作業を日付付きで追記する。
