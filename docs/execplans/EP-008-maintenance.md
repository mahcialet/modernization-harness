# EP-008：継続保守の差分ループ

状態：計画。実装進捗は着手時に更新する。

## 目的
継続保守の差分ループを、根拠とテストで確認できる成果へ分割する。

## 開始条件
承認済みの業務の振る舞いと配備観測が、保守時に変更の影響を比較する基準になっている。

## 実施することと理由
1. source/artifact/config/障害/外部情報のChangeEventを入力にする。
2. stale伝播、必要範囲の再調査、Taskと回帰Scenarioの生成を実装する。
3. opt-inの定期実行と通知先、保持期限、復旧訓練を運用設定へ分離する。
4. テンプレート共通改善を各システムの更新レビューへ展開する。

変更イベントから影響する判断・Task・Scenarioを追跡し、必要範囲を再調査する。定期実行などの運用設定と、各システムがレビューするテンプレート改善を分けて扱う。

データや操作の仕様と検証を先に定め、Agentや実環境への接続は後段で具体化する。

## 完了条件
- [ ] 関係するDecision/Task/Testに変更影響が届く。
- [ ] 差分対象外の旧Runが保持される。
- [ ] 外部情報に出所・取得日・適用版が記録される。
- [ ] 無効な承認や古い知識が現在の有効状態に混在しない。

## PRと証跡
データや操作の仕様、実装、fixture、統合確認をレビュー可能な単位へ分ける。各PRに変更理由、入力Snapshot、実行コマンド、結果、未確認事項を残す。

## 中断・復旧
最後に検証できたcommitとRun/Attemptを記録し、再開時に入力digestと権限を再確認する。外部状態の復元は対象Providerの承認手順で行う。

## 進捗・判断・引継ぎ
着手後に実施済み事項、発見、Decision、残課題、次の作業を日付付きで追記する。
