# EP-003：依存グラフとタスク分解

状態：計画。実装進捗は着手時に更新する。

## 目的
依存グラフとタスク分解を、根拠とテストで確認できる成果へ分割する。

## 開始条件
承認Inventoryがあり、システムの構成要素間で守る入出力・制約・実行条件が調査済みである。

## 実施することと理由
1. 型付きedgeと実システムの循環を保持するグラフを実装する。
2. FindingからDecision候補・調査PoC・Workstream・Taskを生成する。
3. Task DAG、開始条件、repo別変更、ChangeSet、受入Scenarioを検証する。
4. 混在・復旧経路のCompatibility Matrixを作る。

実システムの依存関係を表すグラフを用意し、Findingから判断候補とTaskへ進む。Taskの開始・受入条件と、混在・復旧時の互換性を確認できる形にする。

データや操作の仕様と検証を先に定め、Agentや実環境への接続は後段で具体化する。

## 完了条件
- [ ] runtimeグラフの循環を表現し、Task循環は理由付きで検出する。
- [ ] 共有DB変更がread/write双方へ波及する影響解析fixtureが通る。
- [ ] 前提Decisionが未承認のTaskはreadyにならない。
- [ ] Taskごとに完了検証と復旧条件が存在する。

## PRと証跡
データや操作の仕様、実装、fixture、統合確認をレビュー可能な単位へ分ける。各PRに変更理由、入力Snapshot、実行コマンド、結果、未確認事項を残す。

## 中断・復旧
最後に検証できたcommitとRun/Attemptを記録し、再開時に入力digestと権限を再確認する。外部状態の復元は対象Providerの承認手順で行う。

## 進捗・判断・引継ぎ
着手後に実施済み事項、発見、Decision、残課題、次の作業を日付付きで追記する。
