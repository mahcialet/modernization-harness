# EP-009：Seasar2系システムの調査実証

状態：計画。実装進捗は着手時に更新する。

## 目的
Seasar2系システムの調査実証を、根拠とテストで確認できる成果へ分割する。

## 開始条件
EP-002と許可済み対象repo群がある。

## 実施することと理由
1. Seasar2/Tomcat/AL1またはAL2の利用実態を静的調査する。
2. 独自JAR、DI/AOP、TX、S2Dao/S2JDBC、画面、batch、DB、外部連携を追跡する。
3. 複数repoの境界と実行時情報不足を整理し、追加採取計画を作る。
4. 統合Inventoryを人に提示し、移行候補比較の開始条件を確認する。

静的調査で利用技術とrepo間の境界を確認し、実行時情報の不足には追加採取計画を作る。調査結果を統合Inventoryとして提示してから、移行候補比較へ進めるかを確認する。

データや操作の仕様と検証を先に定め、Agentや実環境への接続は後段で具体化する。

## 完了条件
- [ ] 実際に存在する技術と未確認の技術が区別されている。
- [ ] 3系列の結果と横断照合から重要根拠を追跡できる。
- [ ] 移行先選定に必要なUnknownと比較Scenario候補がある。
- [ ] この実証の成果が現状調査であることを報告できる。

## PRと証跡
データや操作の仕様、実装、fixture、統合確認をレビュー可能な単位へ分ける。各PRに変更理由、入力Snapshot、実行コマンド、結果、未確認事項を残す。

## 中断・復旧
最後に検証できたcommitとRun/Attemptを記録し、再開時に入力digestと権限を再確認する。外部状態の復元は対象Providerの承認手順で行う。

## 進捗・判断・引継ぎ
着手後に実施済み事項、発見、Decision、残課題、次の作業を日付付きで追記する。
