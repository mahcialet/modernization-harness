# EP-007：テンプレートの継続更新

状態：計画。実装進捗は着手時に更新する。

## 目的
テンプレートの継続更新を、根拠とテストで確認できる成果へ分割する。

## 開始条件
同梱ツールのテストと、配布元が管理するファイル・初期化後に導入先が所有するファイル・導入先固有の記録の区分が理解されている。

## 実施することと理由
1. 既存init/status/plan/resolve/applyを監査し、運用上の不足を整理する。
2. schema互換性検査とmigration計画、テンプレート変更の影響を追加する。
3. 署名・配布物hash・release note・GitタグのCIを設計する。
4. 必要に応じて三者自動マージや更新PR作成を追加し、明示承認を維持する。

既存の更新操作を監査して不足を整理し、schema互換性と配布物の確認を拡張する。自動マージや更新PR作成を追加する場合も、適用には明示承認を必要とする。

データや操作の仕様と検証を先に定め、Agentや実環境への接続は後段で具体化する。

## 完了条件
- [ ] 独自設定と調査履歴がテンプレート更新で維持される。
- [ ] 両側変更、削除/更新、所有権変更、同版異内容を検出する。
- [ ] テンプレート版がlockの記録と一致し、次回の比較に使う保存済みのテンプレート内容のhashがlockに記録した基準のhashと一致し、前コミットへ戻して復旧できる。
- [ ] 配布元の署名・hash確認の範囲が報告される。

## PRと証跡
データや操作の仕様、実装、fixture、統合確認をレビュー可能な単位へ分ける。各PRに変更理由、入力Snapshot、実行コマンド、結果、未確認事項を残す。

## 中断・復旧
最後に検証できたcommitとRun/Attemptを記録し、再開時に入力digestと権限を再確認する。外部状態の復元は対象Providerの承認手順で行う。

## 進捗・判断・引継ぎ
着手後に実施済み事項、発見、Decision、残課題、次の作業を日付付きで追記する。
