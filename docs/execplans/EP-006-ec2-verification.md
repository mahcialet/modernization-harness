# EP-006：隔離EC2検証と切替準備

状態：計画。実装進捗は着手時に更新する。

## 目的
隔離EC2検証と切替準備を、根拠とテストで確認できる成果へ分割する。

## 開始条件
EP-005、隔離データ、明示的な検証計画承認がある。

## 実施することと理由
1. 検証専用EC2とDB・queue・外部送信先の隔離を検証する。
2. コンテナと同じ業務Scenarioを実EC2で実行する。
3. OS/EC2条件、性能SLO、混在切替、session、batch、DB互換性を確認する。
4. cutover/rollbackをデータ互換性とともに演習し、独立した本番承認へ渡す。

検証専用環境の隔離を確認してから業務Scenarioを実行し、EC2固有の条件と混在・復旧時の動作を確認する。演習結果は本番操作の承認とは分けて提示する。

データや操作の仕様と検証を先に定め、Agentや実環境への接続は後段で具体化する。

## 完了条件
- [ ] 検証環境から本番DB等へ書けない設定を確認する。
- [ ] 重要業務のHTTP/DB/副作用が規定scopeで比較できる。
- [ ] アプリrollbackとデータ復元の成功証跡がある。
- [ ] 本番承認の対象・期限・手順digestが明確である。

## PRと証跡
データや操作の仕様、実装、fixture、統合確認をレビュー可能な単位へ分ける。各PRに変更理由、入力Snapshot、実行コマンド、結果、未確認事項を残す。

## 中断・復旧
最後に検証できたcommitとRun/Attemptを記録し、再開時に入力digestと権限を再確認する。外部状態の復元は対象Providerの承認手順で行う。

## 進捗・判断・引継ぎ
着手後に実施済み事項、発見、Decision、残課題、次の作業を日付付きで追記する。
