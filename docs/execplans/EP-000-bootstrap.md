# EP-000：契約と基盤の初期構築

状態：計画。実装進捗は着手時に更新する。

## 目的
データ形式・必須項目・参照関係の定義と、それらを検証・管理する基盤の初期構築を、根拠とテストで確認できる成果へ分割する。

## 開始条件
なし。README、AGENTS、実装状況を確認する。

## 実施することと理由
1. System・RepositoryLock・Snapshot・Run・Evidence・Claim・Finding・Inventory・Approvalのデータ形式・必須項目・参照関係と、その検証を実装する。
2. Snapshot固定、ID索引、参照検査、状態遷移、Attempt履歴を決定的なコードで扱う。
3. 同梱schemaとサンプルを使い、矛盾・根拠不足・版の不一致を含むfixtureを用意する。
4. テンプレートのlock、所有権、digestをMVP入力に含める。

データ定義と検証を先に実装する。Agentや実環境への接続は、後続EPでこの定義と検証を使って具体化する。

## 完了条件
- [ ] 無効なID参照・重複・Snapshot不一致を、理由付きで検出できる。
- [ ] 失敗Attemptを再実行しても元の成果物が保持される。
- [ ] 承認した成果物を変えると承認済み扱いが外れる。
- [ ] 端から端までfixture入力から承認待ちInventory案を再現できる。

## PRと証跡
データや操作の仕様、実装、fixture、統合確認をレビュー可能な単位へ分ける。各PRに変更理由、入力Snapshot、実行コマンド、結果、未確認事項を残す。

## 中断・復旧
最後に検証できたcommitとRun/Attemptを記録し、再開時に入力digestと権限を再確認する。外部状態の復元は対象Providerの承認手順で行う。

## 進捗・判断・引継ぎ
着手後に実施済み事項、発見、Decision、残課題、次の作業を日付付きで追記する。
