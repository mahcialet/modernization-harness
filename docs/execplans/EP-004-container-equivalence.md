# EP-004：コンテナと新旧比較

状態：計画。実装進捗は着手時に更新する。

## 目的
コンテナと新旧比較を、根拠とテストで確認できる成果へ分割する。

## 開始条件
EP-003のScenario案と、許可された旧新成果物がある。

## 実施することと理由
1. Compose Providerで別project・DB・stub・volumeを確保し、lease管理する。
2. 初期状態の復元、入力列、非同期収束、出力・DB・副作用の観測を実装する。
3. 版付き正規化、accepted difference、判定不能を比較結果へ含める。
4. クラッシュ後のcleanupと、複数runの干渉検査を実装する。

新旧の環境を分離して確保し、初期状態の復元から観測・比較までを実装する。あわせて、異常終了後の回収と並列runの干渉を確認できるようにする。

データや操作の仕様と検証を先に定め、Agentや実環境への接続は後段で具体化する。

## 完了条件
- [ ] 同じ応答でも通知が2回ならregressionになる。
- [ ] 初期状態が揃わない場合はinconclusiveになる。
- [ ] 独立DB/volumeと外部送信遮断を検証する。
- [ ] 承認した混在構成と失敗時rollbackのシナリオが通る。

## PRと証跡
データや操作の仕様、実装、fixture、統合確認をレビュー可能な単位へ分ける。各PRに変更理由、入力Snapshot、実行コマンド、結果、未確認事項を残す。

## 中断・復旧
最後に検証できたcommitとRun/Attemptを記録し、再開時に入力digestと権限を再確認する。外部状態の復元は対象Providerの承認手順で行う。

## 進捗・判断・引継ぎ
着手後に実施済み事項、発見、Decision、残課題、次の作業を日付付きで追記する。
