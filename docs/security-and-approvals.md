# 権限・承認・証跡

## 信頼境界
調査するソース、README、ログ、Agent出力は分析対象のデータとして扱う。
それらに含まれる操作指示はハーネスの実行権限を変更しない。
実行計画は許可操作、argv、対象環境、データscope、結果保存先を検査してから承認対象にする。

## 承認の粒度
Inventory承認は事実整理の採用、Decision承認は設計判断の採用、Task承認は作業範囲の許可を意味する。
実環境の変更、機密データ取得、外部送信、本番切替は個別の実行承認を付ける。
同じ承認対象の内容が変わればdigestが変わるため、再レビューする。

## 秘密情報と個人情報
設定値は名前と参照先を記録し、秘密値を成果物に複写する代わりにマスキング済みの観測を残す。
必要な原データはアクセス制御・暗号化・保持期限を持つ証跡ストアに保存する。
Agentへ渡すcontextも必要最小限のスコープへ整形する。

## 配布元と導入先
テンプレートのchecksumは内容の一致を確認する。配布者の真正性は信頼するGit履歴・署名・配布経路で別に確認する。
テンプレートはファイルの生成だけを行い、インストールhookや任意コードを自動実行しない。
同梱ローカルツールはsymlink、path traversal、予約領域への書込を検査する。
`.gitignore`は便利な補助として使い、生成時の秘匿化とレビューを主な保護とする。
