# 共通作業方針

管理単位はシステムであり、複数のアプリrepoを同じSnapshotで扱う。
Evidence、Claim、Finding、Decision、Task、VerificationをIDでつなぎ、実施内容と判断根拠を記録する。
A/B/Cは共通の重要領域を独立確認し、封印後にDが一次情報で照合する。
文書は日本語で、実施したこと、次の行動、開始・完了条件、その理由を中心に説明する。
現在有効な方針を本文に置き、過去の判断はADRとRun履歴に残す。
確認済み、推定、未確認、提案、承認済みを区別し、重要な制約には理由と実行可能な代替を添える。
初期調査は静的読み取りとし、実行や外部アクセスは能力と副作用を確認して承認する。
新旧比較は論理初期状態、入力列、HTTP/画面/DB/外部副作用を揃えて観測する。
過去のRunは不変の記録とし、最新Inventoryを承認済み記録から再構成する。
秘密情報は参照とマスキング済み根拠で扱い、保存先と保持条件を記録する。
共通改善は配布テンプレートの改訂で取り込み、個別の設定と業務知識はsystem-opsで保持する。
